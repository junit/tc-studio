# 模型与能力配置：统一保存与交互约定

核对日期：2026-11-12。范围为当前 TC Studio 管理员配置界面。

## 原来的问题

原弹窗在一列长表单中依次放模型连接、执行参数、全部能力与网页策略。能力组件自行读取和保存，
底部“保存配置”只保存模型。结果是用户看见一个窗口，却要理解两套草稿、两次保存和两种生效结果。
取消也不能撤销已经单独保存的能力设置。这个拆分源于代码组件和存储边界，不是产品必须如此。

## 当前交互

入口仍为 BOT 列表底部的“配置”，仅管理员可见。使用现有色彩和表单组件，采用常见设置页的分区导航、
独立内容滚动和固定操作栏；不引入新组件库、字体或前端依赖。

| 分区 | 内容和范围 | 默认展示 |
|---|---|---|
| 模型连接 | 服务级默认模型；未设置专属模型的 BOT 使用它 | 提供商、模型标识、Base URL、密钥 |
| 能力权限 | 当前 issuer/tenant 认证范围内全部 BOT 的已部署能力 | 按数据/内容和执行/协作分组；列出执行上下文及缺失依赖 |
| 网页访问 | 与能力策略相同的认证范围 | 默认关闭的开关、精确域名；超时、大小、并发及频率折叠于高级限制 |

- 只有底部一个“保存更改”，保存所有分区中的修改；无变化时禁用。成功后保留窗口，方便继续检查和测试连接。
- 切换分区不保存、不刷新、不丢弃草稿。高级参数默认折叠；校验失败自动切到对应分区、展开并聚焦错误字段。
- 桌面采用较宽弹窗和左侧导航；手机采用全屏设置、顶部分类，正文独立滚动，保存栏保持可见。
- 关闭、Escape 遇到未保存修改时，提供“继续编辑”与明确的放弃操作。刷新或离开页面使用浏览器的未保存提示。
- 正常底栏只保留关闭与保存，不常驻“暂无未保存更改”和“重新载入”。加载/保存异常或版本冲突时，在错误旁显示重新载入；存在草稿时先确认放弃。正常需要更新服务器配置时关闭再打开即可。
- 侧栏只显示分区导航，版本号继续用于后台 CAS，不作为常驻文案；策略对新任务生效的说明只在相关保存成功后出现。
- 登录身份发生变化时不阻挡认证拦截器的强制刷新，避免旧账户草稿阻止个人工作区清理；草稿不跨身份保留。
- 使用原生模态 dialog，阻止背后界面交互，限制键盘焦点；关闭后恢复原入口焦点。分类支持方向键、Home/End，控件具有可访问名称。
- “获取模型列表”位于模型选择框右侧，由用户明确触发；提供商、地址或密钥变化会取消旧查询并忽略其迟到响应，不在每次打开窗口时自动访问模型服务。
- 模型选择采用显式可编辑下拉框，获取成功后展开候选；重新展开显示全部候选，不用当前已保存模型名过滤其他模型。输入时才按标识搜索，也允许直接填写自定义标识。支持鼠标、方向键、Enter、Escape、Tab；下拉展开时 Escape 只关闭候选，不关闭整个设置窗口。
- 重新载入同时中止旧模型列表与连接测试请求，迟到结果不能填充新配置。切换提供商不暗中重设上下文预算等高级参数。
- “测试已保存连接”明确测试服务器已保存值；模型草稿尚未保存时禁用，避免拿旧连接的成功冒充新配置可用。成功/失败结果紧跟按钮右侧，空间不足时自然换行；Ping 说明放在按钮标题，不另外常驻一行。
- 密钥只保存在当前窗口内存和必要的模型 API 请求里，不进入能力请求、浏览器持久化或文档。空输入遵循后端既有规则：同提供商保留旧密钥，换提供商不沿用。
- 数字允许正常清空后重填；温度 0 保持为 0，不再被 `value || 0.2` 意外改回默认值。

## 一次保存的真实边界

统一用户操作，不等于引入跨存储事务。模型连接（含密钥）仍由原模型配置接口写入权限为 `0600` 的配置文件；
能力开关与网页参数仍由 SQLite CAS 在同一策略事务内保存。没有新增 JSON 能力文件，没有迁移密钥，也没有削弱后端管理员门禁。

保存流程位于 `web/src/lib/agent-settings.ts`，窗口状态位于 `AgentSettingsDialog.tsx`，
`CapabilitySettings.tsx` 只渲染受控草稿，没有独立请求或保存按钮。

1. 先校验各分区的必填项、数值和长度边界。前端校验用于反馈；域名规范化、安全策略和权限仍以后端为准。
2. 仅提交有修改的部分。有能力/网页变更时，先带读取时的 `expected_version` 与 `catalog_version` 调用能力 PUT。
3. 策略 CAS 或目录冲突时立即停止，不再写模型。保留草稿，明确要求重新载入；放弃草稿前再次确认。
4. 策略成功后更新其已保存基线，再按需 POST 模型。若后者失败，提示“能力与网页访问已保存；模型配置保存失败”，保留模型草稿，重试只发未完成部分。
5. 不执行伪回滚，不声称整个保存操作原子化。网络超时/断连可能无法确认服务端是否落盘，需重新载入核对；策略版本不会在未确认时自行推进。
6. 保存中禁止编辑和重复提交；请求有 30 秒客户端超时，窗口卸载时中止请求及忽略迟到回调。客户端中止不承诺撤销服务器已完成的操作。

新任务读取最新能力策略；运行中任务继续其原快照。服务级模型配置仍沿用既有写入行为，
没有在本次界面调整中增加模型配置的跨管理员乐观并发控制。

## 模型下拉修复（2026-11-12）

实测在当前模型名为 `configured-model-not-in-list`、服务返回 `synthetic` 和 `synthetic-v2` 时，
旧原生 `datalist` 虽有两条数据，点击输入框却不出现可选列表。候选提示按已有输入值过滤，
也没有受应用控制的展开行为；“候选已加载”的 DOM 断言无法证明用户真的能选模型。

`ModelCombobox.tsx` 替换该交互：模型框与获取按钮同行，完整列表的展开与输入搜索分别处理，
选择后保留输入焦点，键盘选择不会误提交设置。长标识自动换行，候选限高滚动；
空结果给出明确提示，获取失败后可重试或手动输入。原有跨地址取消和迟到结果保护继续有效。
获取成功不再显示“已获取 N 个模型，展开列表即可选择”整行提示，数量只在展开的列表内显示；
输入框占位文字已表达输入/选择用途，不重复展示常驻说明。预设回退和异常信息仍明确展示。
