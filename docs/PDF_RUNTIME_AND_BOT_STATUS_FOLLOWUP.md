## 根因与修复

### 1. 测试环境和实际开发服务不是同一个 Python

运行进程原来是全局 pyenv Python 执行 `python3 app.py`。该解释器没有 ReportLab，
而项目 `.venv/bin/python` 已有 ReportLab。此前在 `.venv` 跑通的测试，没有证明正在运行的全局解释器也装好了依赖。
`create_pdf_report` 在宿主执行服务端能力；给沙箱增加 ReportLab 导入权限不能修复宿主缺包。

已将当前 `127.0.0.1:8000` 开发服务切换到项目 `.venv`。文档的开发启动入口改为：

```bash
uv sync --locked
TC_STUDIO_APP_ENV=development TC_STUDIO_AUTH_ENABLED=false uv run --locked python app.py
```

生产示例使用同一锁文件环境启动 Uvicorn。pip 部署也必须使用安装 `requirements.lock` 的同一解释器。

[app.py](../app.py) 的 lifespan 新增 [check_pdf_runtime](../core/agent/pdf_reports.py)：
启动时实际生成一页包含中文、英文和数字的 PDF，检查随包字体、正文和字体嵌入。
缺包、缺字体或生成失败时，拒绝启动并给出当前解释器与修复命令。
这条检查验证实际服务解释器，不能只用 `find_spec` 或磁盘锁文件存在代替。

### 2. 发布前只查文件头、EOF、页数不够

[pdf_reports.py](../core/agent/pdf_reports.py) 新增字体资源图检查，并递归检查 Form XObject 内的资源：

- Type0 必须引用唯一有效的 CIDFont，FontDescriptor 不能充当 CID 子字体。
- 非标准字体必须带字体描述和嵌入字体流，避免阅读器替换字体后改变字形和字距。
- 标准 PDF 字体和自带字形的 Type3 字体继续支持；不要求文档没有使用的标准字体也嵌入。
- 失败通过现有原子发布清理流程退出，不登记正式文件、不留下已发布占位文件；`save_file(..., publish=True)` 和 `publish_file` 共用此检查。

这是明确的生成产物契约，不能证明任意第三方 PDF 的视觉质量。上传原始资料不因该规则被改写，
PDF 生成仍优先使用服务端 `create_pdf_report`，并对最终产物渲染验收。

[engine.py](../core/agent/engine.py) 明确要求：报告能力失败就报告失败，允许交付 Markdown；
禁止退回手工拼接 PDF，禁止以未验证的测试文件宣称报告已经修好。
该提示约束有字体发布检查配合，不把模型遵守提示当成唯一防线。

## 公共 / 通用 BOT 是否只能一人使用

**不是。**“通用”仍是业务领域标签；“公共”表示授权范围内复用同一个助手定义。
个人历史、记忆、技能、文件和知识库使用完整身份范围，不因为同时使用公共 BOT 就共享。
资源及权限矩阵见[公共 BOT 隔离审查](PUBLIC_BOT_ISOLATION_AUDIT.md)。

可以将公共 BOT 理解为“一份公共配置 + 每位用户各自的会话与资料空间”。普通使用者不能修改公共基础配置，
有对应管理权限的人维护它；用户自己的偏好仍可保存在个人记忆。与私有 BOT 的主要区别是定义归属和管理权：
私有 BOT 的 owner 可以调整自己的基础配置；公共配置更新会影响后续使用该定义的用户。
实现没有为每位用户复制一条新的 BOT 定义，而是在使用同一定义时分开读取与保存用户状态。
这种隔离指数据、上下文和运行身份，不等于为每位用户部署独立服务进程或分配独立云账号。

当前 `AgentRunManager._run_key` 包含 BOT、issuer、tenant、subject：

| 场景 | 当前行为 |
|---|---|
| Alice 和 Bob 同时使用公共 BOT | 两个独立运行任务，不互相停止 |
| 相同 subject、不同 tenant 使用同一全局公共 BOT | 两个独立运行任务 |
| 同一完整身份对同一 BOT 再发起任务 | 请求停止自己的旧任务，登记新任务；不是无限多会话并行设计 |
| 关闭认证，在两个浏览器打开本地服务 | 都是同一个 `local`，会命中上一行规则 |
| 请求分配到不同 Uvicorn worker | 活动任务仍是进程内状态，跨 worker 协调仍未完成，不能用本轮同进程并发结果替代 |

“请求停止”不等于旧 Python 线程在同一瞬间退出。多用户也受实际模型限流、资源配额和服务容量约束。
本轮没有引入 Redis、PostgreSQL 或扩展到多 Pod。
