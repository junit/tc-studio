# TC Studio 能力目录、沙箱策略与动态扩展

核对日期：2026-11-12。面向当前单机、多服务进程部署。

## 1. 这次解决什么问题

以前，主会话、协同子任务和保存技能各自组装工具。新增一个 PDF 或文件函数，需要改多个执行入口；
技能和主会话的能力也容易不一致。现在用一个能力目录声明名称、适用上下文、依赖和宿主工厂，
执行入口只创建一个 `CapabilitySession`。管理员的开关存在 SQLite，服务进程按任务读取，不靠进程内缓存同步。

这次没有引入 Redis，也没有增加一套 JSON 配置文件。复用现有 `app_settings` 表，设置键由
`core/agent/capabilities.py:POLICY_KEY` 定义，主键维度为设置键 + issuer + tenant。

| 模块 | 责任 |
|---|---|
| `core/agent/capabilities.py` | 能力定义、目录冻结、依赖解析、策略快照、SQLite CAS 和每次任务的资源会话 |
| `core/agent/sandbox_policy.py` | 固定主 Agent 的有效模块集合，以及技能的模块/属性白名单 |
| `core/agent/web_policy.py / web_access.py` | 不可变网页策略、精确目的地校验、固定地址的 TLS 与可终止网络进程 |
| `SqliteWebRequestLimiter` | 同一数据库内跨服务进程的并发租约与自然分钟配额 |
| `core/agent/tools.py:build_bot_tools` | 兼容原有调用者，转交目录工厂组装工具 |
| `AgentEngine.run_agent_stream / execute_subtask` | 使用同一个会话装配逻辑，持有任务资源生命周期 |
| `RunSkillTool` | 使用同一目录的 skill 上下文，生成受控 RPC 代理；不注入真实客户端 |
| `/api/agent/capabilities` | 管理员读取目录和更新当前认证范围内的启用策略 |
| 前端“模型与能力配置” | 模型连接、能力权限、网页访问分区编辑，共用底部“保存更改”；范围和部分失败语义见[配置交互约定](AGENT_SETTINGS_UX.md) |

|---|---|---|---|---|

| `live_urls` | 推拉流地址生成 | 是 | 是 | 是 |
| `files` | 受限 open、文件读取、保存和发布 | 是 | 是 | 是 |

| `charts` | 图表描述生成 | 是 | 是 | 是 |
| `prompt` | 当前用户提示词改进 | 是 | 是 | 否 |
| `memory` | 当前用户长期记忆 | 是 | 是 | 否 |
| `skills` | 技能保存、列举和执行 | 是 | 是 | 否，避免递归启动技能 |
| `delegation` | 同范围内的智能体协同 | 是 | 是 | 否 |
| `knowledge` | 当前用户知识库检索 | 是 | 是 | 否 |
| `bot_creation` | 创建 BOT，仍仅内建全能助手可用 | 是 | 是 | 否 |
| `web_read` | 批准域名的 HTTPS 网页文本；默认关闭 | 是 | 是 | 是 |

“是”表示目录支持该执行上下文，不代表授予新的用户权限。operator、所有权、租户范围、
高风险审批、知识库和文件隔离规则仍在原有业务入口执行。公共 BOT 仍然是共享定义 + 用户独立运行资源。
能力开关按当前 issuer/tenant 生效，作用于此认证范围内的 BOT；不是某个公共 BOT 的全局用户状态。

关闭 `cloud` 会同时移除命名工具、`cloud_call`、`tim_call`、各服务 `*_call`，
以及技能内的兼容客户端代理。URL 生成属于独立的 `live_urls` 能力，有单独开关。
关闭 `files` 时，即使 `pdf` 自身勾选，PDF 也因依赖不满足而不可用。

## 3. 动态管理的准确含义

### 已部署能力：可在线启用/停用

管理员打开左侧“配置”，在“能力权限”或“网页访问”中修改，点击底部“保存更改”。策略变更写入 SQLite。

- 新任务从 SQLite 读取最新策略；另一个已运行的服务进程也在其下一任务读取，不需重启。
- 一次任务及其协同子任务、技能调用使用同一份不可变快照，避免任务中途工具集突然变化。
- 运行中的任务不会立即撤权；紧急情况应同时停止对应任务。此开关不承诺全进程即时熔断。
- 目录和依赖版本变化由部署完成；策略只选择已审查的能力，不接受模块路径、Python 源码或 pip 命令。
- 原有能力保持默认启用以兼容已有任务。新增 `web_read` 声明 `default_enabled=False`，没有明确授权时不绑定入口。
- 新的外部资源能力应显式声明默认关闭。注册不会自动扩大 Python 模块白名单。

### 多进程并发更新

GET 返回 `version`、`catalog_version` 和能力清单。PUT 必须带上读取时的两个版本：

```json
{
  "expected_version": 0,
  "catalog_version": "从 GET 原样取得的版本",
  "disabled_ids": ["cloud"],
  "enabled_ids": [],
  "web_read": {"allowed_domains": [], "allowed_ports": [443]}
}
```

`expected_version` 在 SQLite `BEGIN IMMEDIATE` 事务内比较；过期写入返回 HTTP 409，防止互相覆盖。
目录指纹不匹配也返回 409，避免使用旧目录编辑新设置。非法 ID、重复 ID、额外字段或错误数据类型返回 422。
持久化策略损坏、包含当前目录不认识的禁用项时拒绝启动任务；不会静默恢复全部权限。
更新写入现有审计存储，不记录密钥。

策略 schema 2 将开关与网页参数一起原子保存。`enabled_ids` 用于明确授权默认关闭的能力，
与 `disabled_ids` 不能交叉；启用网页读取还必须配置至少一个批准域名。
旧 schema 1 可读，保存时升级；旧客户端省略新字段时保留既有网页策略，不会自动授予新能力。
若旧客户端明确把网页能力加入禁用列表，则同时撤去该能力的显式授权。

租户管理员只能修改自身 issuer/tenant 的策略；另一个 issuer 即使 tenant/subject 相同也不共享设置。
此设计不是多主机配置分发方案。多 Pod、PostgreSQL 和 Redis 仍留在后续规划中。
现有 AgentRun、审批等待和 SSE 仍是进程内状态，单机多服务进程仍需既有粘性路由。

## 4. 新增能力只注册一次

新增宿主代码和依赖仍需要代码审查、锁文件更新和部署，不提供“不受信 Python 插件热加载”。
适合模型直接导入的小型纯计算库才扩展 Python 白名单；文件、网络、原生文档库优先封装成受控宿主能力。

示例：新增一个按规则检查记录数量的纯数据函数：

```python
from core.agent.capabilities import CAPABILITY_CATALOG, CapabilityDefinition


def bind_record_check(context):
    def check_records(records):
        if not isinstance(records, list) or len(records) > 10000:
            raise ValueError("records 必须是最多 10000 项的列表")
        return {"count": len(records)}
    return {"check_records": check_records}


# 在应用 bootstrap 中导入本模块；必须早于第一次读取目录/创建任务。
CAPABILITY_CATALOG.register(CapabilityDefinition(
    id="record_check",
    title="记录检查",
    description="检查有界记录列表并返回数量。",
    exports=("check_records",),
    contexts=("agent", "delegate", "skill"),
    scope=bind_record_check,
))
```

目录首次使用后冻结，重复名称、保留名称、未知依赖和循环依赖都会被拒绝。
能力接口或安全语义发生变化时需递增定义的 `version`。目录指纹覆盖声明和版本，不是源代码哈希，不能替代部署版本一致性检查。
工厂返回的函数名必须已声明；常量必须是有界可序列化数据，拒绝真实客户端、连接池、manager 和任意宿主对象。
受信函数内部仍要校验身份、数据大小、网络目的地、超时和副作用；注册表不会替代这些业务防护。

- 需要给模型提供参数 schema 的命名 Tool：在定义的 `tool_names` 声明名称，通过 `tools(context)` 工厂返回 Tool 列表。
- 需要会话文件：声明 `requires=("files",)`，通过 `context.files` 复用会话并发布产物。
- `context.kind` 区分主会话、协同和技能；只声明实际支持的上下文，避免给保存技能开放递归调度。
- 技能上下文的函数和命名工具自动生成 RPC 代理，无需再手工修改 worker 的分发名单。
- 若能力需要可取消的昂贵原生计算，应在受控专用 worker 执行；不能把无限计算留在服务主线程。
- 不把密钥、真实客户端或 context 本身写入模型 state。敏感工具依赖继续保存在宿主 `_TOOL_DEPS`。
- 新增第三方依赖必须同步 `pyproject.toml`、兼容依赖声明和三份锁文件；运行环境与 nsjail rootfs 都要包含对应依赖。

## 5. Python 白名单仍然存在

| 项目 | 主会话 / 协同任务 | 保存技能 |
|---|---|---|
| 实现 | 独立 worker 中的 smolagents AST evaluator | AST 预检 + 独立 spawn worker + 受限 builtins/模块代理 |
| 模块 | `collections,csv,datetime,itertools,json,math,queue,random,re,stat,statistics,time,unicodedata` | `csv,datetime,json,math,random,re,time` |
| 成员限制 | 解释器的安全属性/模块结果检查 | `SKILL_MODULE_ATTRIBUTES` 显式成员白名单 |
| 代码预算 | 默认每段 30 秒，宿主工具等待不计入该预算 | 默认 25 秒，人工审批等待补偿 |
| OS 隔离 | macOS 受控 spawn/RPC；Linux 生产要求 nsjail，显式例外除外 | 当前固定 spawn，不自动继承主执行器的 nsjail |

`create_local_evaluator` 显式固定项目允许的有效模块，依赖升级不会自动扩大默认集合。
低层调用者传 `[]` 时保留已经审查过的历史标准库基线。保存技能仍使用更窄的模块/属性策略。
统一能力管理并不意味着两种解释器的 Python 语义、builtins 或 OS 隔离强度完全相同。

文件/PDF/图表能力现在可在三个上下文中使用，例如：

```python
create_pdf_report("报告.pdf", "报告标题", "# 结论\n\n报告正文")
save_file("统计.xlsx", [["项目", "数量"], ["A", 3]], publish=True)
save_file("说明.docx", "# 使用说明\n正文内容", publish=True)
```

技能内的 `open` 也是受限 RPC 文件能力，绝不是 Python 原始内置 `open`。
同时打开 32 个文件、单次读取 512 Ki、累计读取 64 Mi 和现有写入配额继续生效；
二进制通过有界 JSON 编码传输，禁止 pickle。技能最终结果若含 bytes，以显式 `{encoding: "base64", data: "..."}` 返回，
避免 HTTP JSON 编码失败；内部文件调用仍传递原始字节。

技能在主会话中生成的文件共用主会话产物列表，进入该轮 SSE done 和历史附件；
手工运行技能则拥有独立资源会话，返回 `files`。正式发布文件在结束后保留，临时工作区和打开句柄会清理。
同名正式产物仍使用独立存储名，既有文件不会被覆盖。

## 7. 以网络访问为例：后续怎么扩展

### 7.1 已有接口和待实现部分

已实现 `web_read`，导出 `read_web_page(url)`，支持主会话、协同和保存技能；**默认关闭**。
Python 白名单没有开放 `requests`、`httpx`、`socket`。没有提供任意请求头、Cookie、代理、
账号凭据、HTTP 写入、网页脚本执行或文件下载接口。

管理员在“配置 → 模型与能力配置 → 网页访问”填写精确域名并启用“网页读取”；限额位于“高级限制”，
再点底部统一的“保存更改”。开关与参数使用同一个 SQLite CAS 事务保存，下一任务读取新版本。
模型配置和能力策略是不同存储边界；统一保存的校验、冲突和部分成功处理见[配置交互约定](AGENT_SETTINGS_UX.md)。
新能力沿用 `CapabilityDefinition` 注册与统一绑定；执行器没有维护第二份网络函数名单。

启用后的任务可调用：

```python
page = read_web_page("https://docs.python.org/3/library/ssl.html")
print(page["title"])
print(page["text"])
```

示例域名必须先获管理员批准。返回值包括 `url/title/text/content_type/status/bytes_read/truncated/untrusted`；
`untrusted` 固定为 true。过长正文在字节上限内读取后按字符上限截断并明确标记，不把响应伪装成文件附件。
本次没有修改真实能力开关、批准任何真实站点或发起生产外网请求。

### 7.2 调用链和能力划分

调用链：模型调用函数 → 沙箱 RPC → 宿主身份/快照校验 → SQLite 配额 → 独立网络进程 → 有界文本结果。
真实 HTTP 客户端、认证头、Cookie、密钥和连接器配置留在宿主；不得注入模型 state，
也不得作为函数结果或客户端实例返回。工具依赖继续使用宿主 `_TOOL_DEPS` 等私有绑定。
当前网页读取根本不接收凭据。网页正文是外部数据，不能替代用户授权或跳过原有业务鉴权/审批。

后续能力仍分别注册，不通过一个“任意 HTTP”开关授予所有操作：

| 能力 | 状态与允许操作 | 额外约束 |
|---|---|---|
| `web_read` | 已实现，读取批准网页并返回文本 | HTTPS/443、精确域名、无调用者自带认证头 |
| `web_download` | 未实现，拟下载批准文件并发布用户产物 | 应依赖 `files`，复用文件配额、格式检查和用户隔离 |
| 业务 API 连接器 | 未因本次扩展实现，拟按业务操作读取指定服务 | 固定服务、参数 schema 和宿主凭据权限 |
| 外部写操作 | 未因本次扩展实现 | 应补规范化鉴权/审批、幂等和有界重试 |

内网 API 应作为指定连接器授权，不能通过一个“允许内网”选项同时开放全部内网地址。
HTTP GET 也可能触发业务副作用，是否需要审批取决于具体接口语义，不能仅根据方法名决定。
因此批准域名是管理员授予出站读取权限的动作，应选择确认可供读取的站点；不能把通用网页工具当成有副作用的业务连接器。

### 7.3 已实现的网络出口边界

1. **目的地**：仅 HTTPS/443，最多 64 个精确完整域名，IDNA 规范化后精确匹配，不支持通配符或自动包含子域名。
   拒绝 IP 字面量、账号密码、控制字符、反斜线、片段及非 ASCII 请求路径（需 URL 百分号编码）。
   DNS 最多 32 项，全部结果均须通过公网地址检查；任一结果为私网、环回、链路本地、保留、
   元数据或不支持的 IPv6 转换地址时，整次请求拒绝，尚未建立 HTTP 连接。
2. **实际连接**：对已批准的数值 sockaddr 直接调用 socket.connect，不再次用域名解析。
   HTTP Host、TLS SNI 和证书主机名检查仍使用批准域名；核对实际对端地址。
   只选择本次已校验集合的第一个地址，不自动重试 HTTP 请求，不跟随任何 3xx，不读取环境 HTTP 代理。
3. **响应**：仅接受明确声明的 HTML/纯文本类型，不接收 Content-Disposition、压缩编码或未知传输编码。
   响应头总长超过 32 KiB 拒绝；正文按块读，超过字节上限立即终止。
   拒绝 Content-Length/分块编码冲突、提前断开的定长响应和未支持字符编码。
   只返回文本，移除 script/style/template/noscript/svg 内容，不执行 JavaScript，也不渲染远程页面。
4. **生命周期**：DNS、TLS、响应头、正文和文本提取均在可终止的独立 spawn 进程内。
   父进程负责整体截止时间，超时/取消后 terminate、必要时 kill 并回收进程；主动关闭响应和连接。
   主/协同执行器的 close 和 terminate 都向宿主调用传播取消；技能同时继承外层取消及自身预算。
   网络 worker 通过专用 liveness pipe 监视宿主，宿主退出后自行退出，避免只杀沙箱仍留网络工作。
5. **身份和审计**：宿主函数每次核对绑定的 issuer/tenant/subject、任务快照与 operator 权限。
   公共 BOT 使用当前调用用户的身份。审计只保存域名、策略版本、结果、耗时和字节数等元数据，
   不保存 URL 路径/查询、正文或凭据。
6. **策略**：严格拒绝额外字段、错误类型、重复域名、不支持端口和超出上限的限额。
   旧策略、空域名和新部署不会自动开启网络；持久化策略损坏时拒绝启动任务。
   新任务读取新版本，已运行任务继续使用旧快照；管理员关掉开关不等于全进程即时撤权，
   紧急情况仍需停止对应任务。没有实现所有正在运行任务的一键出口熔断。

`core/agent/model_url_guard.py` 服务于模型 Base URL，包含本地模型和显式私网模型的例外。
网页工具没有复用这些放宽项。配置私网模型不授予网页工具访问该私网的权限；
这说明两者策略边界，不是在宣称已复现现有模型调用漏洞。

| 网页参数 | 默认 | 可配置范围 |
|---|---|---|
| 域名 | 空 | 最多 64 个完整域名；启用前至少一个 |
| 端口 | 443 | 首版固定 443，其他值拒绝 |
| 连接/TLS 超时 | 3 秒 | 1–10 秒，且不得大于整体超时 |
| 整体超时 | 10 秒 | 2–30 秒；包含 DNS、读取和提取 |
| 响应正文 | 524288 字节 | 1024–2097152 字节 |

### 7.4 单机多进程如何落地

- 各服务进程部署相同的目录和代码版本，新任务从共享 SQLite 读取设置，沿用 CAS 更新机制。
- 域名、限额与开关存在既有 `app_settings`，配额存 `web_request_rates`、并发租约存 `web_request_leases`，
  审计存既有 `audit_events`。没有新增 JSON 状态文件；网页正文不进入这些表。
- 并发准入通过短 `BEGIN IMMEDIATE` 事务完成，提交并关闭连接后才联网，不持锁等待网络。
  完成或失败时释放租约；异常退出后通过“整体超时 + 5 秒”的过期时间回收。
- 配额采用自然分钟固定窗口，边界两侧可分别使用各自窗口额度，不是滑动窗口。
  同一数据库硬上限 8 个并发、240 次/分钟；认证范围和用户还有各自配置的额度。
  拒绝请求不自动重试；已准入后失败的请求仍消耗本分钟额度，防止以失败重试绕过限流。
- 此实现不要求 Redis。以后多主机时可将配额/租约替换为 Redis、持久化替换为 PostgreSQL，
  保持 `read_web_page` 接口稳定。当前没有统一出口代理、多主机配额或宿主防火墙隔离验收。
- 本能力只使用已声明的 Pydantic 与 Python 标准库，没有新增第三方依赖，无需扩大沙箱导入集合。
- 部署时先升级全部服务进程，再保存 schema 2 设置。旧代码读到新 schema 会拒绝任务，
  不能在共享数据库中长期混跑新旧版本；目录指纹不是部署协调器，也不负责回滚数据库设置。
- 出口需能解析并连接真实公网地址。使用 Fake-IP DNS 的环境会因保留地址被拒绝，不能继承模型端点例外放宽。
  本工具不借用 HTTP_PROXY/HTTPS_PROXY；需要代理出口时应另行实现并验收受控出口适配器。

### 7.5 定向自动化验收

`tests/test_web_access.py` 使用临时 SQLite、真实本地 TLS 服务和真实 spawn/RPC 覆盖：

- 新库/旧 schema 默认关闭、显式授权、域名/端口/类型/上限严格校验和策略损坏拒绝。
- 私网、元数据、IPv6/转换地址、混合 DNS、域名后缀与 URL 混淆拒绝；私网模型例外不影响网页策略。
- 固定连接地址，Host/SNI/证书主机名保留；设置 HTTPS_PROXY 不改变连接；不携带 Cookie/认证头。
- HTML 活动内容移除、正文截断标记、重定向/压缩/下载/非文本/超大响应/断流/错误字符编码拒绝。
- DNS 阻塞和慢响应的进程级超时、取消、父进程 liveness 丢失回收；真实 Agent 停止入口传播取消。
- 三种执行上下文的实际 RPC、跨用户/issuer 拒绝、不可变旧快照与新任务读取新域名。
- 四个真实进程竞争 SQLite 并发槽、全局硬上限、分钟配额、租约过期和联网期间无数据库写锁。
- HTTP 管理员门禁、参数 422、版本冲突 409、跨 issuer 策略隔离和审计不含敏感查询参数。

真实 TLS 测试的本地域名解析与 CA 由受信测试代码注入；生产策略没有放行私网或自定义 CA 的隐藏开关。
浏览器合成 API 回放另验证默认未勾选、空域名/超限参数拒绝、保存、版本冲突、失败恢复及桌面/移动端布局。
测试结果见后续验收记录；这些证据不代表真实公网、Linux/nsjail、OIDC 或多 Pod 已验收。
